# Benchmarks: this decoder vs. CPU decoders and other FPGA decoders

Measured on 2026-09-30 on the owner's laptop and the owner's EP2C5 board. **Everything here is
single-image decode time with the JPEG already in memory (CPU) or already streaming into the
decoder (FPGA): the time to get the file in and the pixels out is not included.** Generated by
`bench/make_benchmarks_md.py`.

## Setup

| | |
|---|---|
| Images | the owner's own photos (`test_images/`: 4000x3000 phone photos of a screen, a 3120x4160 4:2:2 photo, a 1944x2592 4:4:4 photo), three files of the test corpus (`tb/corpus/`, generated from them), and donald.jpg (2048x1365, the photo used since the project started) |
| CPU | Intel Core i7-8550U (Kaby Lake R, 4 cores / 8 threads, 1.8 GHz base, 4.0 GHz turbo), Ubuntu 22.04 |
| CPU clock | the laptop's `performance` power profile, held for the CPU runs (`BENCH_POWER_PROFILE=performance python3 run_bench.py`); average clock measured with `perf stat` during every run: 3.4-3.9 GHz. The laptop is normally in its `power-saver` profile (~1 GHz): earlier versions of this file were measured that way without anyone noticing, which made every CPU decoder look about 4-5x slower (see "Correction" below) |
| CPU decoders | libjpeg-turbo 2.1.2 (C API, `-O2 -march=native` harness), libjpeg 9e (built from `../../jpeg-9e`), stb_image v2.27, Pillow 9.0.1, OpenCV 4.7.0 (`cv2.setNumThreads(1)`), FFmpeg 4.4.2 (its own mjpeg decoder, `-threads 1`, converting to RGB24 like the others); each pinned to one core (`taskset -c 3`), repeated in ~0.1 s batches for >= 1.5 s, median batch reported |
| This decoder | the fast core (`FAST=1`, MCU order, RGB) at 95 MHz on the EP2C5 (`quartus/fpga_jtag`, 4,473 of 4,608 LEs, timing met at 95 MHz): **clock counts measured on the board** with the decoder clock gated so that streaming time is excluded, identical to the cycle-exact simulation for every image; and the compact core (`FAST=0`, `quartus/fpga`, 50 MHz) from simulation |
| Output | CPU decoders: RGB, raster order (libjpeg-turbo default and Pillow/OpenCV with smoothed chroma, `-nosmooth` and this decoder with replicated chroma: same pixels as libjpeg 9e `djpeg -nosmooth`); this decoder: RGB in MCU order (8x8 / 16x16 tiles, each pixel tagged with x, y) |
| Energy | CPU: RAPL package energy over the run / decodes (includes background package power); FPGA: PowerPlay vectorless estimate x decode time (low confidence) - neither is precise enough to compare energy closely |

Not measured: the laptop's Intel UHD 620 hardware JPEG decoder and GPU decoders (not available here).
